### What I Learned

- Containers and volumes are separate Docker resources.
- Data stored in a container's writable filesystem can be lost when the container is removed.
- Named volumes exist independently of container lifecycles.
- The same named volume can be mounted into different containers.
- `docker inspect` can be used to examine volume mounts and container configuration.
- Port publishing makes services inside containers accessible through the host machine.
- A path inside a container is not automatically the same path on the Ubuntu host.
- Removing a container does not remove its named volumes.
- Volumes must be explicitly removed if their stored data is no longer needed.

### Problems Encountered

- Initially tried to edit `/usr/share/nginx/html` on the Ubuntu VM instead of inside the container.
- Encountered `Permission denied` because the files were owned by `root`.
- Initially accessed the host without specifying port `8080`, reaching a different Nginx service.
- Learned to distinguish between the host machine, the container filesystem, and Docker-managed volume storage.

### Docker Compose Configuration

The configuration includes:

- `name` — project name.
- `services` — defines the containers managed by Compose.
- `image` — specifies the Docker image.
- `restart` — defines the container restart policy.
- `ports` — publishes container ports to the host.
- `volumes` — mounts persistent storage into the container.
- `external: true` — tells Compose to use an existing volume instead of creating a new one.

### Problems Encountered

**1. `build` versus `image`**

Initially used:

`build: .`

Docker Compose attempted to find a Dockerfile in the current directory and failed because no Dockerfile existed.

Learned that:

- `build` is used when building a custom image from a Dockerfile.
- `image` is used when specifying an existing Docker image.

For this exercise, `image: nginx:latest` was the correct choice.

**2. Multiple Compose files**

Initially ran `docker compose ps` from the repository root instead of the `docker/nginx/` directory.

Docker Compose picked up a different configuration file (`docker-compose.yml`) in the root directory, which caused confusion and returned an empty service list.

Learned that the working directory matters when running Docker Compose commands because Compose searches for configuration files in the current directory.

**3. Obsolete `version` attribute**

Encountered a warning that the `version` attribute in an older Compose configuration is obsolete and ignored by modern Docker Compose.

Learned that the current Compose specification does not require the `version` field.

### What I Learned

- Docker Compose allows defining and managing container configurations using YAML.
- A `compose.yaml` file describes services and their configuration.
- `docker compose up` creates and starts the services.
- `docker compose up -d` starts services in detached mode.
- `docker compose ps` displays the status of services managed by the current Compose project.
- `docker compose down` stops and removes Compose-managed containers and networks.
- Existing named volumes can be reused through external volume declarations.
- Compose simplifies container management compared to manually running multiple `docker run` commands.
