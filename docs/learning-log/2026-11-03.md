## Problems & Troubleshooting

### SSH connection and host key mismatch

- The initial SSH connection on port 22 was refused.
- SSH access was configured on port 2222.
- The next connection attempt reported a host key mismatch.
- Verified the new ED25519 host key fingerprint directly on the Ubuntu VM.
- Confirmed that the fingerprint matched the new key reported by the SSH client.
- Removed the stale host key entry from the host machine's `known_hosts` file.
- Successfully connected to the VM.

## What I Learned

- How to organize project documentation.
- Why SSH uses host keys to verify server identity.
- Why a host key mismatch should be investigated rather than blindly ignored.
- How to remove a stale SSH host key entry safely after verifying the new fingerprint.

## Remote Access with Tailscale

### What I did

- Installed Tailscale on the Ubuntu VM, MacBook and Android phone.
- Connected all devices to the same private Tailscale network.
- Configured SSH access to the VM using its Tailscale IP.
- Enabled the Tailscale daemon to start automatically:

  `sudo systemctl enable --now tailscaled`

### Verification

- Confirmed that `tailscaled` is enabled.
- Confirmed that `tailscaled` is active and running.
- Rebooted the Ubuntu VM.
- Successfully reconnected to the VM from the phone using Termius after reboot.

### What I learned

- How Tailscale provides private network connectivity between devices.
- How to use a Tailscale IP address for remote SSH access.
