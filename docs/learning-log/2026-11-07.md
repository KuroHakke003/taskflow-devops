# Learning Log — November 7, 2026

## 1. Dockerfile and Custom Application Image

Created a Dockerfile for the TaskFlow FastAPI application.

**Dockerfile configuration:**

```dockerfile
FROM python:3.12

WORKDIR /app

COPY requirements.txt ./

RUN pip install --no-cache-dir -r requirements.txt

COPY app/ ./app/

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Built the image:**

```bash
docker build -t taskflow:v1.0.0 .
```

Learned:
- How Docker builds an image from a Dockerfile.
- The purpose of `FROM`, `WORKDIR`, `COPY`, `RUN`, `EXPOSE`, and `CMD`.
- How Docker build cache works.
- Why copying `requirements.txt` before application source code improves build efficiency.
- The difference between a Docker image and a running container.
- How the application import path `app.main:app` corresponds to the project structure.

## 2. Running the API Container

Attempted to run the TaskFlow API image as a standalone container.

The container exited because the application could not connect to PostgreSQL.

**Root cause:**

The database URL initially used `localhost`:

```text
postgresql+psycopg://taskflow:taskflow@localhost:5432/taskflow
```

Inside a container, `localhost` refers to that same container, not the VM or another container.

This demonstrated why multiple application services need proper container networking.

## 3. Environment Variables and Configuration

Created a `.env` file based on `.env.example`.

Updated the database connection URL to use the PostgreSQL Compose service name:

```env
DATABASE_URL=postgresql+psycopg://taskflow:taskflow@db:5432/taskflow
```

Learned:
- How environment variables configure an application.
- How Docker Compose passes environment variables using `env_file`.
- Why `localhost` is not interchangeable with another container's service name.
- How Compose provides DNS resolution between services on its default network.

Created a `.gitignore` file to exclude:

```gitignore
.env
__pycache__/
*.py[cod]
.pytest_cache/
.venv/
venv/
```

Important distinction:
- `.env` contains local configuration and must not be committed.
- `.env.example` is a shareable configuration template and should remain in Git.

## 6. Docker Networking

Docker Compose automatically created a default network:

```text
taskflow-devops_default
```

Both `api` and `db` joined this network.

The API connects to PostgreSQL using:

```text

```

Learned:
- Compose creates a default network for services.
- Services can communicate using their service names.
- Internal container communication does not require publishing every port to the host.
- The PostgreSQL port does not need to be exposed publicly for the API to access it.

## 8. Important Lessons and Troubleshooting

- `localhost` inside a container refers to that container itself.
- Docker Compose service names can be used as internal DNS hostnames.
- `environment` and `env_file` serve different configuration purposes.
- `service_healthy` allows a dependent service to wait for a successful healthcheck.
- A named volume preserves database files independently of the container lifecycle.
- `docker compose config` is useful for validating configuration before starting services.
- Compose automatically creates a network and volume when they are declared.
- Compose files in different directories can represent separate projects. The working directory and selected Compose file matter.
- A Dockerfile describes how to build an image; Compose describes how services are configured and run together.
