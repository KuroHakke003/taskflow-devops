# Learning Log — November 12, 2026	

## Focus: Prometheus Alerting & Telegram Notifications

### 1. Alertmanager Telegram Integration
- Configured Alertmanager to send notifications to my personal Telegram chat.
- Connected Prometheus to Alertmanager using the `alertmanagers` configuration.
- Created a Telegram receiver named `taskflow-telegram`.
- Configured notification grouping, intervals, and resolved notifications.
- Customized Telegram messages using HTML formatting and Alertmanager templates.
- Enabled `send_resolved: true`.

### 2. Troubleshooting File Permissions
- Encountered a `permission denied` error when Alertmanager tried to read the Telegram bot token.
- Investigated the Alertmanager container user (`nobody`, UID/GID 65534).
- Fixed file access using Linux ownership and permission settings:
  - Changed the token file's group to GID 65534.
  - Set file permissions to `640`.
  - Set the secrets directory permissions to `711`.
- Verified that Alertmanager could read the token without exposing it or committing it to Git.

### 3. Telegram Chat ID Configuration
- Discovered that Telegram returned `403 Forbidden` because the configured chat ID was incorrect.
- Started a conversation with my Telegram bot.
- Retrieved my personal Telegram user ID and updated the Alertmanager configuration.
- Successfully received the first Telegram alert notification.

### 4. Testing Alert Lifecycle
- Created a temporary `TelegramTest` alert using:
  `vector(1)`
- Verified that Prometheus detected the alert and marked it as firing.
- Received a `FIRING` notification in Telegram.
- Changed the test expression to:
  `vector(0) > 0`
- Restarted Prometheus to apply the updated rule.
- Checked the Prometheus rules API and confirmed that `TelegramTest` entered the `inactive` state.
- Eventually received the `RESOLVED` notification in Telegram.
