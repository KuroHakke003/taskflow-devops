# Learning Log — 2026-11-23

## Helm Chart Validation and Configuration Alignment

Today I finalized the local configuration and validation of the TaskFlow Helm chart.

### Work completed
- Aligned Helm Deployment selectors and Pod labels with the existing Kubernetes Deployment (`app: taskflow-api`).
- Configured consistent resource names for the API Deployment, Service, ServiceAccount, ConfigMap and Ingress.
- Updated the Service selector to match API Pod labels.
- Aligned Ingress configuration with the existing host, TLS secret and backend Service.
- Disabled automatic ServiceAccount token mounting.
- Aligned API image pull policy and resource limits with the live deployment.
- Verified PostgreSQL resource references and persistent storage configuration without modifying the existing database.

### Validation
- `helm lint helm/taskflow` — passed.
- `helm template taskflow helm/taskflow -n taskflow` — passed.
- Verified the rendered resource names and selectors.

### Safety
The Helm chart was validated locally but was not installed into the live cluster. Existing Kubernetes resources and PostgreSQL data were left untouched.

### Key takeaway
Helm templates must match existing Kubernetes resource names, selectors, labels and dependencies when preparing a chart for migration or adoption. Local rendering and linting help catch configuration issues before applying changes to a live cluster.
