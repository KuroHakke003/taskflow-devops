- Inspected logs from the `api_service`, PostgreSQL, and Nginx containers.

- Reviewed HTTP status codes in the API access logs:

### Docker log commands and Linux pipelines

Practiced the following commands and concepts:

- `docker logs api_service` — display container logs.
- `--tail 10` — show the most recent 10 log lines.
- `--follow` — stream new log output.
- `--since 15m` — show logs from the last 15 minutes.
- `grep ERROR` — filter lines containing the specified text.
- `grep 500` — search for lines containing the HTTP 500 status code.
- `grep "200 OK"` — search for a phrase containing a space.
- `grep GET` — filter GET request entries.
- `grep HTTP/1.1` — select HTTP request log entries.
- `wc -l` — count lines.
- `|` — pass the output of one command to another (a Linux pipe).

Combined these tools to count HTTP request log entries:

```bash
docker logs api_service | grep HTTP/1.1 | wc -l
```

The command returned `18` for the available log history at the time of the exercise.

Also practiced time-scoped filtering and pipelines, for example:

```bash
docker logs api_service --since 15m
docker logs api_service --since 15m | grep 500
```

Learned that search patterns must match the actual log format. The request line contains `HTTP/1.1" 500`, not the phrase `HTTP 500`. A filter that returns no matches is not proof of health unless the search pattern and time window are correct.

## Key Concepts Learned

- Docker captures container stdout and stderr, which can be inspected with `docker logs`.
- Logs help identify which component reported an error and provide context for troubleshooting.
- A traceback should be followed to its root exception rather than stopping at the first error line.
- Docker Compose service names are resolved through Docker's internal DNS on the Compose network.
- A stopped service may no longer be resolvable by its Compose service name.
- Linux pipes allow small utilities such as `grep` and `wc` to be combined into useful diagnostic pipelines.
- Time filters reduce noise and make recent incidents easier to investigate.
- An empty grep result can mean either that no matching events occurred or that the search pattern was incorrect.
