# Learning Log — November 10, 2026

## Focus: Monitoring & Operations — Prometheus and Node Exporter

### What I Learned

Today I continued working on monitoring and observability for my TaskFlow infrastructure.

I learned how Prometheus and Node Exporter work together to collect and monitor system metrics.

### 1. Node Exporter

- Added Node Exporter to Docker Compose.
- Learned how Node Exporter exposes Linux system metrics for Prometheus.
- Configured host networking and host filesystem access.
- Learned why `network_mode: host` and `pid: host` are useful for monitoring the host system.
- Used `--path.rootfs=/host` to allow Node Exporter to inspect the host filesystem.
- Verified that Node Exporter was running and accessible.

### 2. Prometheus

- Added Prometheus to Docker Compose.
- Configured Prometheus using `prometheus.yml`.
- Learned how scrape configurations work.
- Connected Prometheus to Node Exporter.
- Verified that the Node Exporter target was UP.
- Learned how Prometheus discovers and scrapes metrics from configured targets.
- Added persistent storage using a named Docker volume.

### 3. Prometheus Access Through Tailscale

- Configured an additional Tailscale Serve path for Prometheus.
- Learned how reverse proxy paths and URL prefixes affect web applications.
- Configured Prometheus using:
  - `--web.external-url`
  - `--web.route-prefix`
- Fixed redirect and routing issues.
- Successfully accessed the Prometheus interface remotely through Tailscale HTTPS.

### 4. PromQL Fundamentals

Practiced querying system metrics directly in Prometheus.

**Memory:**
- `node_memory_MemTotal_bytes`
- `node_memory_MemAvailable_bytes`
- Calculated available memory in GiB.
- Calculated RAM usage percentage.

**CPU:**
- `node_cpu_seconds_total`
- Learned the difference between CPU modes such as `idle`, `user`, and `system`.
- Learned why CPU metrics are counters.
- Practiced using `rate()` to calculate CPU utilization.
- Calculated average CPU usage across logical CPU cores.
- Learned the difference between `avg()` and `sum()` aggregations.
- Used PromQL aggregation to count logical CPUs.

**Disk:**
- `node_filesystem_size_bytes`
- `node_filesystem_avail_bytes`
- `node_filesystem_free_bytes`
- `node_filesystem_readonly`
- Learned why Node Exporter reports multiple filesystem time series, including `tmpfs`.
- Filtered the root filesystem using `mountpoint="/"`.
- Calculated root filesystem usage percentage.

### 5. Monitoring Concepts

Reviewed the difference between:
- Metrics — numerical measurements collected from a system.
- Alert Rules — conditions evaluated against metrics.
- Alerts — notifications or events generated when conditions are met.
- Alertmanager — responsible for handling and routing alerts.

### Key Takeaways

- Prometheus periodically scrapes metrics from configured targets.
- Node Exporter exposes Linux system metrics in a Prometheus-compatible format.
- Counters require functions such as `rate()` when measuring their change over time.
- PromQL supports filtering, arithmetic operations, and aggregations.
- Monitoring requires understanding what each metric actually represents, not just copying queries.
