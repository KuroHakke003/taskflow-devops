# Learning Log — November 11, 2026

## Focus: Monitoring & Observability — Grafana Dashboards

### What I Learned

Today I continued building the monitoring stack for my TaskFlow infrastructure.

The main goal was to integrate Grafana with Prometheus and create a custom dashboard for monitoring the Ubuntu VM.

### 1. Grafana Deployment

- Added Grafana Enterprise to Docker Compose.
- Used the official Docker image: `grafana/grafana-enterprise:13.3.1-ubuntu`.
- Configured container name, port mapping, and restart policy.
- Created a named Docker volume `grafana_data`.
- Mounted persistent storage at `/var/lib/grafana`.
- Learned why Grafana needs persistent storage for its configuration, dashboards, and other application data.
- Verified the Compose configuration using `docker compose config`.
- Started Grafana and verified that the container was running.
- Tested the HTTP endpoint and confirmed that Grafana redirected requests to `/login`.
- Successfully accessed Grafana remotely through Tailscale.

### 2. Prometheus Integration

- Added Prometheus as a Grafana data source.
- Configured the Prometheus server URL using Docker Compose service discovery:
  `http://prometheus:9090`
- Learned why `localhost:9090` would not work from inside the Grafana container.
- Understood how Docker Compose networking allows containers to communicate using service names.
- Successfully tested the Prometheus connection.

### 3. Building a Custom Dashboard

Created a custom dashboard called `TaskFlow Infrastructure`.

Learned how to:
- Create dashboard visualizations.
- Select Prometheus as the data source.
- Switch between Builder and Code modes.
- Write PromQL queries directly in Grafana.
- Choose visualization types.
- Configure units, minimum and maximum values, and panel titles.

### 4. System Metrics and PromQL

Created monitoring panels using the metrics collected by Node Exporter.

**RAM Usage**
- Used `node_memory_MemTotal_bytes` and `node_memory_MemAvailable_bytes`.
- Calculated RAM usage percentage using PromQL.
- Created a Gauge visualization.
- Configured the range from 0 to 100%.

**CPU Usage**
- Used `node_cpu_seconds_total`.
- Applied `rate()` to calculate CPU activity over time.
- Calculated CPU utilization percentage.
- Created a CPU monitoring panel.

**Disk Usage**
- Used `node_filesystem_size_bytes` and `node_filesystem_avail_bytes`.
- Filtered the root filesystem using `mountpoint="/"`.
- Calculated disk usage percentage.
- Created a Gauge visualization.

**Network Traffic**
- Used `node_network_receive_bytes_total` for incoming traffic.
- Used `node_network_transmit_bytes_total` for outgoing traffic.
- Applied `rate()` to calculate network throughput.
- Identified the correct network interface: `enp0s3`.
- Learned why filtering by network interface is important when Node Exporter also reports Docker bridge interfaces.
- Configured separate incoming and outgoing traffic panels.
- Used Time series visualizations to observe traffic changes over time.
- Learned how to display network throughput in bytes per second.

**System Uptime**
- Used `node_boot_time_seconds`.
- Used `time()` to retrieve the current Unix timestamp.
- Calculated system uptime by subtracting boot time from the current timestamp.
- Created a Stat visualization.
- Learned that `node_boot_time_seconds` is a Gauge, not a Counter, so `rate()` is unnecessary.

### 5. Visualization Concepts

Learned when to use different Grafana visualizations:

- Gauge — useful for current percentages and resource utilization.
- Time series — useful for observing changes and traffic over time.
- Stat — useful for displaying a single important value, such as system uptime.

### Key Takeaways

- Grafana visualizes metrics but Prometheus remains responsible for collecting and storing them.
- Grafana can query Prometheus directly through the internal Docker network.
- PromQL expressions can be reused in Grafana panels.
- Different metric types require different approaches.
- Choosing the correct visualization makes monitoring information easier to understand.
- Network interfaces must be filtered carefully to avoid mixing unrelated traffic.
