# Learning Log — 2026-11-19

## Kubernetes Configuration, Resource Management, Autoscaling, and StatefulSets

Today I continued working on the Kubernetes deployment of TaskFlow and implemented several important infrastructure improvements.

### 1. ConfigMaps

- Created a ConfigMap named `taskflow-config`.
- Moved non-sensitive application configuration into the ConfigMap.
- Learned how Kubernetes injects ConfigMap values into containers as environment variables.
- Separated application configuration from the container image and deployment manifest.

### 2. Secrets

- Created a Kubernetes Secret named `postgres-secret`.
- Stored PostgreSQL database credentials in the Secret.
- Configured the API and PostgreSQL workloads to retrieve credentials using `secretKeyRef`.
- Updated the API's `DATABASE_URL` to use environment variable substitution instead of hardcoded credentials.
- Added the Secret manifest to `.gitignore` to prevent accidental exposure of credentials.

### 3. Resource Requests and Limits

Configured CPU and memory requests and limits for both application components.

**TaskFlow API:**
- CPU request: `100m`
- CPU limit: `500m`
- Memory request: `128Mi`
- Memory limit: `256Mi`

**PostgreSQL:**
- CPU request: `100m`
- CPU limit: `500m`
- Memory request: `128Mi`
- Memory limit: `512Mi`

Learned the difference between resource requests and limits:
- Requests define the resources Kubernetes uses when scheduling Pods.
- Limits define the maximum resources a container can consume.

Used `kubectl top pods` to inspect actual CPU and memory consumption.

### 4. Horizontal Pod Autoscaler (HPA)

- Created an HPA using the `autoscaling/v2` API.
- Configured it to target the `taskflow-api` Deployment.
- Set minimum replicas to 1 and maximum replicas to 3.
- Configured CPU utilization target to 50%.
- Verified that the Metrics Server provided CPU metrics.
- Created a temporary BusyBox Pod to generate load.
- Observed HPA scale the API from 1 to 2 and eventually 3 replicas.

This demonstrated how Kubernetes can automatically adjust application capacity based on resource utilization.

### 5. PostgreSQL StatefulSet Migration

Migrated PostgreSQL from a Deployment to a StatefulSet.

- Created `postgres-statefulset.yaml`.
- Created a Headless Service named `postgres-headless`.
- Configured the StatefulSet to use `postgres-headless` as its governing service.
- Reused the existing `postgres-pvc` instead of creating a new volume.
- Preserved the existing Persistent Volume and its binding.
- Kept the regular `db` ClusterIP Service so the API could continue connecting to PostgreSQL through `db:5432`.
- Scaled the old PostgreSQL Deployment down before starting the StatefulSet.
- Verified that `postgres-0` reached the Running and Ready state.
- Verified that the API remained operational after the migration.
- Removed the obsolete PostgreSQL Deployment manifest and Kubernetes Deployment resource.

Learned why StatefulSets are useful for stateful workloads: they provide stable Pod identities and work with persistent storage.

### 6. Database Backup

- Created a PostgreSQL backup using `pg_dump`.
- Saved the dump as `taskflow-backup.sql`.
- Inspected the generated SQL dump.
- Confirmed that the Kubernetes database contained zero task records at the time of backup.
- Added `*.sql` to `.gitignore` to prevent database backups from being committed to the repository.

**Note:** A backup was created and inspected, but a restore operation has not been performed yet.

### 7. Git and Repository Updates

- Updated Kubernetes manifests.
- Added API Service, ConfigMap, HPA, Headless Service, and StatefulSet manifests.
- Removed the old PostgreSQL Deployment manifest.
- Verified that sensitive files and database backups were excluded from Git.
- Committed and pushed the Kubernetes infrastructure changes to GitHub.

## Key Takeaways

Today I learned how to manage application configuration and credentials in Kubernetes, control container resource consumption, and automatically scale application replicas using HPA.

I also migrated PostgreSQL from a Deployment to a StatefulSet while reusing its existing persistent volume.

TaskFlow now has a more complete Kubernetes configuration with separate API and database workloads, persistent storage, resource management, and horizontal autoscaling.
